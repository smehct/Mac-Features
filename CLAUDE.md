# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single AutoHotkey v2 script, `mac-features.ahk`, that adds macOS-style shortcuts to Windows for a user with a Mac keyboard and a Swiss German (de-CH, 0807) layout. "Cmd" is bound to both the Win key (`#`) and left Alt (`<!`), because it's unclear which one the Mac keyboard's Cmd key reports. Use left Alt only (`<!`), since AltGr on de-CH arrives as LCtrl+RAlt.

- `Cmd+G` types `@` (`SendText`, so it doesn't depend on the layout).
- `Cmd+C/V/A/Z/S/P/F` and `Cmd+Shift+S` send the matching Ctrl shortcut (Win+F would open the Feedback Hub). They're bound to the Win key only, so Alt+letter stays free for menu shortcuts. This replaces Windows' own Win+V (clipboard history), Win+A (quick settings), Win+Z (snap layouts), Win+S (search), Win+P (projection menu) and Win+Shift+S (Snipping Tool). `$#s` uses the keyboard hook so that `Send("#s")` from Cmd+Space doesn't trigger it. `Cmd+Shift+Z` (redo) sends Ctrl+Y.
- Tapping `Cmd` alone opens the emoji panel (`#.`) instead of Start. `~LWin` sends the `vkE8` mask key so Windows doesn't open Start, and `~LWin Up` checks `A_PriorKey`, which ignores script-generated input. Start is still reachable with Ctrl+Esc.
- Windows Search (`#s`) and the Alt+Tab switcher always open on the primary monitor, no matter where the mouse, the foreground window or the last-used taskbar is (tested). The user is fine with that, so there's no workaround.
- `Cmd+Tab` is AHK's built-in `AltTab` action as a custom combination (`LWin & Tab`), so the switcher stays open while Cmd is held. This replaces Task View.
- `F3` opens Task View (`#{Tab}`), like Mission Control. This replaces "find next" in apps.
- F-keys work like the Mac media keys: F1/F2 change brightness (laptop panel via WMI `WmiMonitorBrightnessMethods`, external monitors via DDC/CI `dxva2` in `AdjustBrightness`), F7/F8/F9 do previous/play-pause/next, F10/F11/F12 do mute/volume down/volume up. This replaces the apps' own F1 (help), F7–F12, etc.
- `Option+5/6/8/9` type `[ ] { }`, `Option+7` types `|`, `Option+Shift+7` types `\`, and `Option+N` types `~` (directly, not as a dead key), like the Mac de-CH layout. Left Option arrives as `<!`, right Option as AltGr (`<^>!`), so both are bound.
- `SC029`↔`SC056` are swapped, because a Mac ISO keyboard sends the §/° key and the </> key the wrong way round under de-CH.
- `Cmd+Q` sends Alt+F4, but not when the desktop or taskbar is active, because there Alt+F4 opens the shutdown dialog.
- `Shift+Backspace` sends `{Delete}`, because the Mac keyboard has no forward-delete key. `Send` releases Shift first, so in Explorer files go to the Recycle Bin instead of being deleted permanently (which Shift+Del would do).
- `Cmd+Space` opens Windows Search (`#s`), like Spotlight. It's bound to the Win key only and replaces Windows' input-language switcher on Win+Space.
- `Cmd+Shift+4` does a region screenshot like on macOS: a dimmed overlay over the whole virtual screen, a crosshair, drag a frame (Esc cancels), then a thumbnail at the bottom right in a frosted-glass frame. You can drag the thumbnail into any app as a file, swipe it to the right to save it right away, or click it to open the image. If you leave it alone, the PNG moves to the Desktop after about 6 s (hovering keeps it open).

## Vorschau (PDF viewer in `vorschau/`)

A Preview-like PDF viewer/editor, opened with `Cmd+O` on a selected PDF in Explorer (`OpenVorschau` in `vorschau/vorschau.ahk`, included by `mac-features.ahk`) or `AutoHotkey64.exe vorschau\vorschau.ahk file.pdf`. README.md documents the features for the user; keep it in sync.

- Stack: `app/` is a plain-JS page (`index.html`, `style.css`, `app.js`, no build step) using vendored `lib/pdf.min.js` (pdf.js 3.11 UMD, rendering) and `lib/pdf-lib.min.js` (writing). `server.ps1` is a hidden PowerShell `HttpListener` on 127.0.0.1 that serves `app/`, reads/writes PDFs (`/file`, `.pdf` only), stores prefs (`/prefs`) and runs the Claude CLI (`/claude`, POST starts a job, GET `?id=` polls). Every non-static request needs the random token from `%LOCALAPPDATA%\Vorschau\server.json`. The server exits after 180 s without a `/ping` from a window.
- The window is `msedge.exe` (else `chrome.exe`) `--app=` with its own `--user-data-dir` under `%LOCALAPPDATA%\Vorschau\profile`. Edge is missing on this machine, Chrome is used. The window title is `<name> – Vorschau` (en dash), which `IsVorschau()` matches for the Cmd hotkeys that forward to Ctrl combos (Win+R, Win+O, Win+G, Win+= ... are overridden there only).
- Markups are page-local "base units" (points of the page at its own `/Rotate`; our extra rotation is a CSS rotate on `.inner`, `toLocal()` inverts it). `buildBytes()` reloads the original bytes with pdf-lib, reorders/copies pages, applies form values (`S.form`), strips old `/Text` annotations, and draws every markup via `drawMarksPdf` (`vp.convertToPdfPoint` maps view to user space, so rotated pages work). Per page with markups it also writes `/VorschauData` (JSON of marks, base64 images, extra rotation) and tags the content stream it drew into with `/VorschauMarks`; `unpackVorschau()` (called by `addDoc`) removes that stream, the data and our `/Text` annots (`/NM` starting `vorschau-`) and undoes the extra `/Rotate`, so a re-opened file is editable and nothing is drawn twice. Comments become real `/Text` annotations; on load pdf.js annotations are imported back as editable `note` marks and form widgets become `.fw` inputs (`annotationMode: ENABLE_FORMS` so the canvas does not draw them twice).
- `vorschau/build.ps1` downloads the official Ahk2Exe into `%LOCALAPPDATA%\Vorschau\tools` if needed and compiles `vorschau.ahk` to `vorschau/Vorschau.exe` (committed; it must stay next to `server.ps1` and `app/`). In the compiled exe `A_LineFile` is not the exe path, so `OpenVorschau` uses `A_ScriptFullPath` and the start guard also checks `A_IsCompiled`. A second launch posts the path to `/queue`; open windows poll it every 1.5 s and open the file as a new tab, otherwise (nobody picks it up within 3 s) a new window is started. `install.ps1` registers the exe under HKCU for "Open with" on PDFs (the default app itself can only be set by the user in Windows).
- Tabs: everything per document lives in `S` (`DOC_KEYS`); `stashActive()`/`activate()` swap it with the tab object and `rebuild()` recreates the DOM, so page objects keep their marks. `openBytes` opens in a new tab unless the current tab is empty. Ctrl+W/T/Tab are partly reserved by the browser, so the visible UI (close button, middle click, `+`) is the reliable path and Ctrl+Shift+Left/Right switches tabs.
- Layout is toolbar (basics incl. text/object selection toggle, highlight, note, measure), mark bar (draw tools), tabs, document. Both bars are user-arrangeable (`setArranging`, body class `arranging`, banner `#arrbanner`; right-click a bar or `#b-arrange`): the mark bar order/hidden keys are stored in `prefs.json` as `tools`, the top bar as `top` (left/right group lists plus hidden); separators exist only in the default layout (`DEFAULT_ITEMS`). Clicking the file name opens a rename/save popup; `/rename` on the server renames inside the folder. Copy/cut/paste of a mark goes through `localStorage` (`vorschauClip`) so it works across windows; `keydown` handles Ctrl+C/X for marks because automated key events do not trigger native copy events.
- Claude gets no CLI tools. Instead `ACTION_HELP` tells it to append one ```` ```vorschau-actions ```` JSON block; `cleanActions()` whitelists/validates it (page range, numbers, colours, max 40), `showReply()` shows it as a preview card and `applyActions()` applies it as ONE undo step (text phrases are located with `findPhrase()` on the pdf.js text items; unknown phrases are reported). PDF text is untrusted, so nothing runs without the user clicking "Anwenden". The floating `#askfab` next to selected text only shows while `/claude?status=1` (cached `claude auth status`) says the CLI is signed in; `/whoami` suggests the comment author.
- Bars: the top bar is one flex row (`.group` is `display: contents`) with two default flexible spacers around the title; spacers (`.sp`, ids `sp-flex-*` / `sp-fix-*`) are items like buttons and are dragged in from the arrange banner. Handles and comment symbols keep a constant screen size via `--hs` / `--ns` (1/zoom).
- `prompt()` is not available in every host, so dialogs are in-page (`askText`, `askConfirm`, `#modal`). The Claude job runs `claude -p --tools ""` (no tools: PDF text is untrusted input).
- Testing: start `server.ps1 -Root vorschau -State <dir>\server.json` hidden, open `http://127.0.0.1:PORT/index.html?t=TOKEN&file=<urlencoded path>` in the Browser pane (it has DPR 1.5 and a click coordinate scale of 1024/800, so divide CSS px by 1.28 for clicks); `window.__S` exposes the state. A pane without focus does not fire `blur`, so dispatch it by hand when testing text editing.

## Commands

AutoHotkey v2 is installed per-user (via `winget install AutoHotkey.AutoHotkey`):

```powershell
$ahk = "$env:LOCALAPPDATA\Programs\AutoHotkey\v2\AutoHotkey64.exe"
& $ahk mac-features.ahk                      # run / reload (#SingleInstance Force replaces the running copy)
& $ahk /ErrorStdOut /validate mac-features.ahk   # syntax check only
```

The Mac keyboard's Cmd key reports as the Win key. Windows' own Win+G (Xbox Game Bar) and Win+Z (snap layouts) fire even though AHK grabs the hotkeys, so both are turned off with `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced\DisabledHotkeys = "GZ"`. That takes effect after an Explorer restart or a new sign-in.

Autostart is a shortcut in `shell:startup` (`Mac Features.lnk`) that points to this script. `install.ps1` sets everything up: it installs AHK, creates the autostart shortcut, applies the Win+G registry fix and starts the script. It can be re-run safely. `README.md` is the German user guide and must be kept in sync whenever shortcuts change.

AHK is a GUI exe, so stdout only gets captured with `Start-Process ... -RedirectStandardOutput <file> -Wait` and `/ErrorStdOut=UTF-8` plus `FileAppend(..., "*")` in the script. To test functions headlessly, write a scratch script that `#Include`s `mac-features.ahk`, calls e.g. `Capture(0,0,400,300)`, then `ExitApp`. Hotkeys and the drag gesture need a real user.

## Architecture notes

- Everything is raw Win32/GDI+/Shell calls through `DllCall`, with no AHK libraries:
  - capture: `BitBlt` with `CAPTUREBLT`, then GDI+ `GdipSaveImageToFile` with the PNG encoder CLSID `{557CF406-1A04-11D3-9A73-0000F81EF32E}`. A wrong CLSID makes GDI+ return status 10 and leaves a 0-byte file.
  - drag out: `SHParseDisplayName`, then `SHBindToParent` and `IShellFolder::GetUIObjectOf` (vtable 10) to get an `IDataObject`, then `SHDoDragDrop` with a NULL drop source, so there's no custom COM `IDropSource`. This needs `OleInitialize` at startup. Don't use `SHCreateDataObject` here: its object offers no formats (no CF_HDROP), so Chromium/Electron apps ignore the drop.
- When you click the thumbnail, the screenshot moves to the Desktop and opens in Snipping Tool. `OpenInSnippingTool` looks up the AppX ProgID of `Microsoft.ScreenSketch` under `HKCR\.png\OpenWithProgids` and calls `ShellExecuteEx` with `SEE_MASK_CLASSNAME`. Things that don't open the file: passing it on the command line (`SnippingTool.exe <file>`), the `ms-screensketch:edit?filePath=` protocol, and `IApplicationActivationManager::ActivateForFile` (the app is full-trust).
- Screenshots go to `%TEMP%\MacShots` first and only move to the Desktop when the thumbnail expires or gets clicked. If it gets dragged, the file stays in temp, because drop targets may read it later. Temp files older than 2 days are deleted at startup.
- The thumbnail is two windows. One is an acrylic pane (`SetWindowCompositionAttribute`, `ACCENT_ENABLE_ACRYLICBLURBEHIND`, plus DWM rounded corners and a border colour). The other is an owned picture window on top of it, because GDI content drawn inside an acrylic window turns semi-transparent. Moving or destroying the thumbnail must handle both windows (`MoveThumb`, `FinishThumb`). A mouse-down that moves mostly rightward is a swipe (`SwipeThumb`), anything else starts the OLE drag.
- The thumbnail runs on a 25 ms `SetTimer` (`ThumbTick`) rather than in the hotkey thread, so a new screenshot can finalize the previous thumbnail.
- All GUIs use `-DPIScale` and screen coordinates, so sizes are physical pixels (AHK v2 is per-monitor DPI aware). GUIs that must not steal focus use `WS_EX_NOACTIVATE` (`+E0x08000000`), and the frame lines are click-through (`+E0x20`).
